### 2.3 追问 A–D（不能证明的标 unknown）

**A. 变更日期是否可确认为"行业归属变更日期"？——可以（有源码+文档双重证据）**

- 故"变更日期=行业归属变动日期"**由接口文档与源码共同确认**，非字段名推断。证据位置：本节源码摘录 + AKShare 1.18.22 `stock_industry_change_cninfo.__doc__`。

**B. 能否证明返回的是完整变更历史？——不能，标记 unknown**
- 只能证明"在查询区间内返回的记录"，**无法证明这是该股有史以来全部变更**（接口未提供记录总数/游标/完整性校验）。源码默认区间为 `20091227~20220713`，全量查询受该默认区间约束（显式传区间可覆盖，但后端历史起点是否为 2009-12-27 未知）。
- 结论：**unable to prove completeness → unknown**。

**C. 最新记录停留在 2021 是否意味着此后无变化？——不能证明，标记 unknown（存在数据更新缺口迹象）**
- 反证：2025/2026 显式区间查询返回空，且源码默认 end_date 为 `20220713`。
- 两种可能均无法排除：①该公司 2022 后行业归属确未变更（但 5 只股票全部恰好止于 2021-12-17，概率上更像是**同一批分类体系在 2021-12-17 集中更新后接口未再维护**）；②接口数据源存在更新缺口/已停止维护。
- 结论：**无法区分"无变化"与"更新缺口"→ unknown；但存在明确的数据新鲜度风险，不可作为 2025/2026 当前分类依据**。

**D. 能否按分类标准独立重建历史分类？——可以（同一标准内可回溯），但需固定单一标准**
- 记录含 `分类标准` + `变更日期` + 四级行业字段，可按指定标准筛选后按变更日期排序，取"不晚于目标日的最近一次变更"重建该标准下的历史归属。
- 约束：标准间口径不一致（申万/中证/巨潮/恒生/证监会并存），**必须先固定单一标准再做时序重建**，不可混用；且受 B（完整性 unknown）与 C（新鲜度缺口）限制。
- 结论：**结构上可重建，但完整性与时效性为 unknown**。

## 四、最终回答（6 问）

**1. 巨潮历史分类能否支持可靠的历史时点分类？**
**部分支持，附条件**。优点：变更日期语义有文档+源码确认、含四级层级、可按标准筛选、无重复无空值、支持区间查询。限制：完整性无法证明（B=unknown）、数据新鲜度停在 2021 且 2025/2026 查询为空（C=unknown/存在缺口）、多标准需固定其一。结论：**仅可用于"历史区间内的、单一标准下的"分类回溯，且必须标注时效边界；不可作为 2025/2026 当前分类源**。

**2. 申万行业目录能否取得稳定的股票成分映射？**
**本环境未能取得（unknown）**。行业目录稳定可取（二级 131 / 三级 336，含层级），但成分映射接口 `sw_index_third_cons` 两次失败（Length mismatch / No tables found），历史分类 xls SSL 失败。`second/third_info` 是目录不是成分，**不能充当个股映射**。换数据源（如申万官网/其他镜像）是否可恢复 = unknown。

**3. 新浪当前分类能否作为独立分类体系使用？**
**只能作为"当前板块归属快照"参考，不足以作为 V1.0 独立标准**。原因：无层级、无标准编码、无分类生效/更新时间、无历史成分变更、部分板块调用失败、无法与申万/中证建立可靠对应。

**4. 哪个分类体系最适合成为本项目 V1.0 唯一标准？**
**巨潮行业分类标准（cninfo，单一标准固定）** 是当前证据下最合适的候选：它是唯一同时具备"证券代码映射 + 多级层级 + 权威标准 + 带日期可变记录 + 实际可调用"的源，且由官方（巨潮资讯）发布、AKShare 有专门接口。但**必须先解决数据入库与时效缺口**（见问 6），并在结果中固化 `classification_standard=巨潮行业分类标准`。申万/新浪作为交叉参考，不作为标准。

**5. 板块指数日线数据还有哪些可行来源？**
本轮未新增板指日线调用；已知：东财 `stock_board_industry_hist_em`（本环境断连，换出口可重试）、申万指数日线函数不存在。**待验证候选（尚未实测 → unknown）**：中证/国证行业指数日线（如通过 `index_zh_a_hist` 按行业指数代码取）、同花顺行业指数（`stock_board_industry_index_ths`）、新浪行业板块指数历史。需在后续授权轮次实测，本轮不推断其可用性。

**6. 当前是否已经具备启动 D3-1 的条件？**
**不具备**。阻塞性质仍为 `blocked_by_data_dependency`，且本轮新增两点证据强化了阻塞：①申万成分映射不可用；②巨潮历史数据停在 2021、时效缺口。启动 D3-1 前至少需：
1. 将选定标准（巨潮）的分类数据**采集入库**到本地受控表（含 code/行业层级/标准/来源/采集时间）；
2. 明确历史回溯规则并**标注时效边界**（变更日期仅到 2021，2022+ 为缺口/unknown）；
3. 确认并实测至少一条可用的**板块指数日线源**；
4. 补齐全市场 `stock_info` 基数。
上述均属数据工程前置，未完成前不进入 D3-1。

## 6.1 修正 2025/2026 错误分类（KeyError ≠ auth_required）

第三轮 JSON 把 2025/2026 的 `KeyError: '变更日期'` 记为 `failure_category=auth_required`——**该分类无证据支持，本轮撤销并修正**。

底层接口实测（000001，2025 区间）：

| 项 | 实测值 |
|---|---|
| 接口 | `https://webapi.cninfo.com.cn/api/stock/p_stock2110` |
| 请求参数 | `scode=000001, sdate=2025-01-01, edate=2025-12-31` |
| HTTP 状态码 | **200** |
| Content-Type | `application/json;charset=utf-8` |
| 原始响应正文（脱敏，全文 73 字节） | `{"total":0,"records":[],"resultmsg":"success","count":0,"resultcode":200}` |
| AKShare 解析结果 | `pd.DataFrame([])` → 无"变更日期"列 → 抛 `KeyError: '变更日期'` |
| 最终异常类型 | `KeyError`（解析层），**非** HTTP 认证异常 |
| 是否确实空数据 | **是**（`records=[]`, `total=0`, `count=0`） |

2026 区间（sdate=2026-01-01, edate=2026-11-21）原始响应同样为 HTTP 200 + `{"total":0,"records":[],"resultmsg":"success","count":0,"resultcode":200}`。

**结论**：
- **已证实**：2025/2026 HTTP 200、`resultcode=200`、`resultmsg="success"`、`records=[]` → 是**空数据**，不是授权失败、不是错误页面、不是接口结构变化。
- **已证实**：`KeyError` 是 AKShare 对空 `records` 构造 DataFrame 后访问缺失列所致，属**解析层异常**，归类 `auth_required` 错误。
- **修正后分类**：`failure_category=empty_response_parsed_as_keyerror`（空响应导致解析异常），`is_empty_data=true`，`freshness_status=empty_response_confirmed`。
- 底层响应可取得，故不触发 `response_body_unavailable`。
