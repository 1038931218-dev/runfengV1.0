## 一、任务书七问逐项回答

### 1. 最近一次分类变更日期
**2024-02-08**（`change_response_semantics.json`）。对 601398/600519/000651 三只样本股票，change 接口在 2024 年度各返回 1 条记录，VARYDATE=2024-02-08，标准 F001V=008001（中上协），F002V=中国上市公司协会上市公司行业分类标准——这是一次**标准换代**记录，非个股行业普通变更。**该日期仅为本次三只样本的观察结果，不外推为全市场结论。**

### 2. 2025/2026 是否有真实更新
**个股变更：未见。** 三只股票查 2025、2026 年度，底层 HTTP 200 但 `records:[]`、`total:0`（真实空结果，见第 3 问）。
**行业级统计：有更新。** `stock_industry_pe_ratio_cninfo` 的"变动日期"分别为 2023-11-30、2024-11-29、2025-11-28、2026-11-20（四个日期行数分别为：2023-11-30 **109 行**、2024-11-29 **120 行**、2025-11-28 **120 行**、2026-11-20 **120 行**）——这是中上协行业分类的**行业级市盈率统计**按日更新，不是个股分类变更。
> 必须区分：行业级统计更新 ≠ 个股行业归属变更。前者更新到 2026，后者在三只样本中最新止于 2024-02-08（样本观察，非全市场结论）。

### 3. 空响应代表"无变更"还是"数据缺失"——已定性
`change_response_semantics.json` 底层 HTTP 捕获给出决定性证据：2023/2025/2026 三次查询全部 **HTTP 200、`resultcode:200`、`resultmsg:"success"`、`total:0`、`records:[]`**。AKShare 抛 `KeyError: '变更日期'` 是空 DataFrame 缺列导致的解析异常，与 D3-0 freshness 结论一致。
> **结论：空响应 = 该区间确无变更记录（真实空结果），不是 HTTP 错误，不是接口数据缺失。** 这解答了任务书悬置的问题。

### 4. 变更日期是否等于生效日期——unknown
接口字段名为"变更日期"（VARYDATE），无任何官方说明其等于"生效日期"。维持 D3-0/D3-1 的 `unknown` 判定，不得把变更日期直接宣称生效日期。

### 5. 能否还原某股票在指定历史日期所属行业——能力有限，语义未证
- change 接口提供个股的历史行业（含四级：行业门类/大类/中类/次类 + 行业编码 + 标准编码 + 变更日期），结构可支撑 SCD2。
- 但：三只样本历史止于 2024-02-08、变更日期语义 unknown、样本在 2023/2025/2026 无记录（仅样本观察，非全市场结论）。
- **结论：结构上可构建历史区间，但生效语义未证实 + 数据缺口大，不能保证任意历史日期的准确还原。**

### 6. 北交所新旧代码映射是否有可靠历史依据——unknown
承接 D3-1：北交所现行 920 段 profile 20/20 成功、旧段 830/831/835/836/832 返回 0 行；旧→新代码映射关系未取得。本轮未发现新的映射依据，维持 unknown。

### 7. 分类标准升级后历史数据如何保留——有证据但未完整
三只样本在 2024-02-08 的换代记录显示（样本观察，非全市场结论）：中上协标准（008001）替换旧标准，且个股 change 记录中保留旧标准编码（如 008013 巨潮旧、008018 申万旧，见 D3-1 classification_sample_30.json）。结构上"按标准编码分别保留历史"可行，但：
- 无版本字段（巨潮目录终止日期全空，见下）；
- 换代前后的完整历史序列未逐只核验。
> 结论：升级历史有样例证据，但缺版本标识与完整序列，**不足以支撑生产级历史追溯**。

## 二、关键新发现：巨潮目录无版本/生效/失效日期
`cninfo_category_termination_audit.json`：三个标准目录（008002/008001/008003）的目录总行数分别为 294/577/512，**"终止日期"字段 notna 全部为 0**；字段集中无"版本/修订/生效"字段。此前 D3-1 数据模型"目录终止日期可作版本边界"的表述**被推翻**——目录根本不提供这些日期。（注：`coverage_timeliness_probe.json` 旧版 `termination_date_nonnull` 曾误填为目录行数 294/577/512，本轮已修正为 0，与独立审计 notna=0 一致。）

## 三、历史时点规则设计（字段均标注数据依据）

| 字段 | 设计语义 | 数据依据 | 状态 |
|---|---|---|---|
| `effective_from` | 分类生效日期 | 接口仅提供"变更日期"（VARYDATE），语义未证实 | **unknown（阻塞）**——不得以变更日期冒充 |
| `effective_to` | 分类失效日期 | 无接口提供；不得用目录终止日期填充（该字段全空） | **unknown（阻塞）** |
| `classification_standard` | 分类标准 | change 有标准编码（008002/008001/008003 等）；profile 无编码 | 部分可取（change）/unknown（profile） |
| `classification_version` | 分类版本 | 无任何接口提供版本/修订字段 | **unknown（阻塞）** |
| `source` | 数据来源 | 接口标识可明确（cninfo_change/cninfo_pe_ratio 等） | 可取 |
| `collected_at` | 采集时间 | 本轮请求时间戳可记录 | 可取 |

> 规则设计原则：六个字段中仅 `classification_standard`（部分）、`source`、`collected_at` 有数据依据；`effective_from`/`effective_to`/`classification_version` 无依据，一律标 unknown，**不伪造日期**。SCD2 生效语义未确认前，历史时点规则保持设计阻塞。

### 3.1 空结果处理纪律
- change 接口空 `records:[]` = 确无变更（已证实），不得当作"数据缺失"补造记录。
- 无分类记录或过期 → `data_status=unknown/stale`，不计入有效覆盖分子。
- 不得把未知分类填成 0 或"其他"行业。

## 四、D3-2.3 结论

- **已证实**：最近个股变更为 2024-02-08（仅 601398/600519/000651 三只样本观察，非全市场结论）；行业级统计更新至 2026-11-20；空响应=真实空结果；巨潮目录无版本/生效/失效日期。
- **unknown**：变更日期=生效日期、北交所新旧代码映射、任意历史日期准确还原、分类版本标识。
- **BLOCKED**：分类历史可追溯性——生效语义未证实、三只样本历史止于 2024-02-08（非全市场结论）、版本字段缺失。
- **未解除**：SCD2 历史时点规则因 `effective_from/effective_to/version` 无依据保持设计阻塞。
